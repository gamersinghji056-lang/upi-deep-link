Connection flow

1. Install & open APKBefore connection, the app clearly explains location, SIM, network, battery and credit-SMS access.
2. Review permissionsPermissions are requested one by one. Credit-SMS access is used only for payment verification after explicit consent.
3. Pair deviceEnter the one-time dashboard code. The backend returns a device credential once and binds it to the device + SIM fingerprint.
4. SIM continuity checkEvery heartbeat, diagnostics report and credit confirmation includes the same SIM fingerprint. A changed fingerprint is rejected.
5. UTR verificationCustomer submits UTR on the payment page. The APK parses a new bank credit SMS locally and sends only the parsed UTR, amount, sender and timestamp. Matching UTR + amount marks the payment successful.

Security rules

One-time pairing codeStored as SHA-256 and invalid after use or expiry.
Device tokenReturned once to the APK; backend stores only its hash.
SIM-bound requestsBackend rejects heartbeat, diagnostics and credit-SMS calls when the SIM fingerprint changes.
No raw inbox uploadThe backend does not need full SMS bodies or historical inbox access. Only parsed payment-credit evidence is uploaded.
If this APK is distributed through Google Play, SMS permissions are restricted and require an eligible financial-transaction use case, prominent disclosure/consent and Play Console permission review. Device-SMS verification is evidence from the paired phone; for high-value settlement, a bank/acquirer API remains the strongest source of truth.
